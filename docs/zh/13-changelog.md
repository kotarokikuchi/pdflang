# 13. 变更记录

[← 实用范例](12-recipes.md) · [目录](README.md)

每个版本改了什么，以及这些改动可能在你这边破坏什么。

版本仍处于 `0.x`，因此次版本号的提升允许带来破坏。一旦发生，条目会写清楚破坏
了什么、如何适配。这里不会有悄悄的改动。

---

## 0.17.0

### 新增

- `pdfl pixelcompare` 为每个阶段显示进度条——光栅化两个文件、比较、写出查看器。
  只有当 stderr 是终端时才绘制，因为进度条靠覆盖自己那一行来工作，而日志文件没有
  可移动的光标；被重定向时它保持安静。`--quiet` 在任何情况下都会让它闭嘴。
- `pdfl pixelcompare` 的 `--jobs <n>` 同时比较这么多页，默认每个 CPU 一个：150 dpi
  的 41 页从 3.6 秒降到 1.2 秒。只有比较是并行的——pdfium 把每一次调用都串行在一把
  全局锁后面，所以光栅化并行不了，这也是提速三倍而不是八倍的原因。取值不影响报告：
  页面按页码顺序折回，因此诊断、它们的顺序和指纹都完全一致，查看器写出的文件也一样。

  > 这里默认每个 CPU 一个，而 `test` 和 `watch` 默认 `--jobs 1`。那边一个任务是
  > 一个子进程，各自抱着一份文档；这边页面已经在内存里，线程共享它们。

## 0.16.0

### 新增

- `pdfl pixelcompare` 按外观而不是文字逐页比较两个 PDF，并报告不同像素的占比。
  只是发生位移的页面会先对齐再比较，这样一个像素的偏移不会淹没真正要紧的改动。
- `pixelcompare` 的 `--viewer <文件夹>` 会写出一个自包含的应用——不用 CDN、不用
  打包器、不用服务器——可以在两个文件之间擦除、翻转或淡入淡出，差异就地着色：
  红色表示消失的墨，绿色表示新增的墨，蓝色表示分量相同而颜色不同。页码条可以
  筛成 **Changed only**，方向键也跟随筛选——在长文档里，翻过那些没动过的页面
  才是真正费时的部分。

---

## 0.15.0

### 新增

- `if` / `else if` / `else`，作为**表达式**：它的值是所走分支的最后一个表达式，
  与函数已经遵循的规则相同。因此它既能当值用
  （`const LIMIT = if coated { 300 } else { 260 }`），也能当作语句的守卫，不需要
  第二套语法。没有走到的分支返回 `null`，且每个分支有自己的作用域——给分支外
  已经存在的变量赋值，仍然更新的是外面那个。

---

## 0.14.0

### 修复

- `--var` 现在也能到达 `pdfl test` 和 `pdfl watch`，不只是 `pdfl run`。此前两者
  都没有把它转给自己派生的子进程，因此读取 `vars.*` 的脚本根本无法被测试或监视——
  不论内容是什么，每个用例或文件都会以"was not provided"失败。

## 0.13.0

### 破坏

- **`pdfl pack` 不再打包电子表格**（`.xlsx`、`.xls`、`.ods`），并会说明留下了
  哪个文件。没有任何 `data::` 函数能打开它们，带着它的软件包安装顺利，却在第一次
  查询时失败。若你此前打包了电子表格，请先导出为 `.csv` 或 `.json`。

### 新增

- `run` 的 `--tags TAG`，筛选运行哪些 check。可重复；check 只要带有其中任一
  标签就会运行。
- `inspect` 与 `lint` 的 `--json`，以及 `doc` 的 `--output json`。所有子命令
  都可被程序读取了。
- `--output sarif` 与 `--output junit`，凡是可以选择报告格式的地方都支持——`run`、
  `compare`、`watch` 和 `fix`。SARIF 是 GitHub code scanning 读的格式，JUnit 是
  任何 CI 的测试面板读的格式。
- `pdfl completions <shell>` 输出 bash、zsh、fish、elvish 或 powershell 的补全
  脚本。
- 每个命令都可用的 `--quiet`，关闭 stderr 上的进度与确认信息。错误照常显示，
  `print()` 也不受影响——那是脚本自己的输出，吞掉它就改变了脚本的行为。
- `data::load_dataset` 与 `data::lookup_value` 除 `.csv` 外也读 `.json`：数组的
  数组，或对象的数组——由第一个对象按文件中的书写顺序确定列名。
- `pdfl test <script>` 用脚本跑一整个文件夹的 PDF，并把每份报告与记录在旁边的那份
  比对：配置文件一旦开始查出不一样的东西，失败的是测试，而不是下游某个人的一天。
  `--update` 用于记录预期报告。
- `pdfl test` 的 `--jobs <n>` 同时运行这么多用例，每个都是独立进程。8 个 41 页的
  文件：`--jobs 1` 用 8.9 秒，`--jobs 8` 用 1.1 秒。默认仍是 `1`，因为每个任务都
  把一份文档放在内存里；`--jobs 0` 表示每个 CPU 一个。
- `pdfl watch` 也有 `--jobs <n>`：文件由子进程校验，因此批量的一轮同样可以扩展
  （8 个 41 页的文件从 9.5 秒到 1.2 秒）。写出的报告与 `--jobs` 取值无关。
- `pdfl watch` 的 `--events`：等待文件系统通知，而不是用定时器。这是可选项而非
  默认值——在 NFS 或 SMB 挂载上，inotify 只报告本机写入的内容，网络热文件夹会
  就此失声。如果监视器建不起来，watch 会说明并退回定时器。
- `pdfl watch` 的 `--journal <文件>`：只追加的已校验记录，每个文件一行 JSON。用
  同一个 journal 再跑会跳过它覆盖的文件——在五千个里跑到四千个被打断的批处理，
  只需再跑剩下的一千个——但仍然报告它们的结论，所以续跑的批处理绝不会声称文件夹
  是干净的。
- `pdfl watch` 的 `--timeout <秒>`：超过这个秒数就杀掉某个文件的分析，并报告为
  被拒——一条发现，`check_name: "timeout"`——而不是让批处理卡住。`.pdfl` 脚本的
  递归已经有深度限制，所以这个选项是为脚本造不成的情况而设的：pdfium 在畸形或
  恶意的 PDF 上死循环或卡住。

### 需要留意

- 没有任何 check 携带的标签会**报错**，而不是空通过。否则标签拼错的流水线将
  什么都不校验，却报告文件干净。
- `rule` 不带标签，因此 `--tags` 会跳过它——这与不带标签的 check 是同一个答案。
- JSON 报告新增 `checks_run`，即运行过的 check 与 rule。它不提升
  `schema_version`，因为忽略未知字段的读取方不会因此出错。JUnit 需要它：诊断只
  会点到有所发现的 check，而一次干净的运行若报告为零个测试，CI 会认为这次运行
  从未发生。

### 修复

- `pdfl watch` 现在在最新的那个文件稳定下来时就醒来，而不是最多再等一整个轮询
  间隔。在 `--debounce 3000` 下，一个到达的文件约 3 秒后被报告，而不是最多 6 秒。

## 0.12.0

### 新增

- 脚本可以从命令行接收值：`--var 名称=值`，以 `vars.名称` 读取。未传入的值会
  指出应当提供它的那个参数，而不是解析为空。
- 四个用 `visual::` 比较两份文档的完整示例：`proof.pdfl`、`reprint.pdfl`、
  `scope.pdfl` 和 `intake.pdfl`。

### 破坏

无。从不提及 `vars` 的脚本行为与此前完全一致。

## 0.11.0

### 破坏

**诊断标识符的形态变了。** 原先是 `PDFL-001`，即本次运行内的计数；现在由发现
本身推导而来，例如 `PDFL-093751a2`。

> 凡是按 `PDFL-\d+` 匹配的都不再匹配。作为交换，在某个发现之上插入 check 后，
> 它的标识符不再改变——这正是"已批准基线"得以维持的前提。

**无法读取的输入以 `10` 退出，而不是 `2`。** 此前损坏的文件与被判不合格的文件
对流水线来说无从区分。

> 如果你的 CI 把 `2` 当作"这个文件被拒绝"，那么在文件根本未被判定时它现在会
> 看到 `10`。发现仍使用 `0`、`1`、`2`；脚本语法错误仍是 `3`。

### 新增

- check 可以声明自身发现的严重级别：
  `check "..." severity: warning { ... }` — `error`（默认）、`warning`、`info`。
  正是它让 `--fail-on warning` 有了作用对象。
- JSON 报告以 `schema_version` 开头，消费方由此知道自己在读哪种形态。它仅在
  读取旧输出的一方会被破坏时才提升；新增字段不会提升它。

## 0.10.0

### 破坏

**发布目标由 `x64` 改名为 `amd64`**，因此所有资产名称都变了。

**不再发布可移植归档**，仅保留 Linux amd64 的那一个。

> 凡是下载 `pdfl-<版本>-linux-x64.tar.gz`，或使用 Linux amd64 之外任何可移植
> 归档的，都需要修改。在 CI 中请从 `.deb` 安装——本文档中的范例已相应更新——
> 或者在无法安装的场合使用 Linux amd64 的 tarball。

### 修复

- 将文档与源码逐一比对后发现的两处缺漏：`text::detect_personal_data` 与
  `text::detect_pii` 接受一个未被记录的可选字符串参数；`fix::reorder_pages`
  在不同语言的文档里写法不一致。
